# 設計成果物一覧

[本書の目次](../README.md)｜[ケースブック本文](../BOOK.md)

同じ家電アフターサービス改善案件を、開発工程でレビューする成果物として整理した。本文は判断の経緯、付録は参照資料、このフォルダは文書ごとの合意事項と実装・検証条件を扱う。

| 文書番号 | 成果物 | 主な内容 | 関係する本文 |
| --- | --- | --- | --- |
| REQ-001 | [要件定義書](01-requirements.md) | 目的、業務範囲、業務ルール、R-01～16、受入・変更条件 | 第1～3章 |
| EXT-001 | [外部設計書（基本設計）](02-external-design.md) | システム境界、機能、画面、帳票、外部IF、利用者に見える状態 | 第4・5・7～9章 |
| INT-001 | [内部設計書（詳細設計）](03-internal-design.md) | データ辞書、キー、処理順序、版、排他、非同期、ジョブ、配備 | 第5～10・13章 |
| TST-001 | [テスト計画・仕様書](04-test-plan-specification.md) | 120シナリオ、詳細手順、非機能・移行・運用の別ゲート | 第11章 |

## 文書の読み方

要件定義書で「何を満たすか」を確認し、外部設計書で「利用者と他システムからどう見えるか」、内部設計書で「どのデータと処理で実現するか」を追う。テスト・移行・運用の文書で、完成・切替・継続の判定を確認する。

物語中のレビュー日程・成果は学習用のケースである。文書管理表の責任者はケース内の役割を示し、実在者の署名や実機試験済みの保証を意味しない。詳細設計で補った値はTRC-001のDD番号で識別する。
