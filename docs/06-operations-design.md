## 1. 運用の目的・時間・責任

応答の復旧と業務の回復を分け、外部受付・予約・引当の状態を取り残さずに業務を継続する。

| 役割 | 平常時 | 障害時・判断 |
| --- | --- | --- |
| 受付 | 確認、照会、受付、顧客への留保説明 | 再登録を止め、代替窓口と次連絡を案内 |
| 高橋／SV | 未引受け、期限、担当割当、教育 | 優先度・代替業務・顧客連絡を調整 |
| 岡本／IT運用 | 接続、権限、監視、構成、容量 | ツール停止、外部照合、復旧、技術当番 |
| 森／品質保証 | 規約、安全案内、根拠承認 | 誤案内・安全の封じ込め、訂正・専門判断 |
| 青木／品質担当 | 回帰、判定証跡、欠陥管理 | 再開条件の確認 |
| 松田／責任者 | 範囲・投資・優先順位 | 公開範囲縮小、切戻し、重大影響の判断 |
| 接続先部門 | 正本とインタフェース維持 | 外部ID照合、制限・仕様変更の連絡 |

有人対応は9:00～18:00、年末年始を除く。技術障害は時間外も当番へ通知するが、通常の顧客折返しと修理訪問を24時間提供する意味ではない。優先30営業時間分、通常4営業時間は社内目標として管理する。

## 2. 監視項目と対応判断

| MON-ID | 観測するもの | 検知・判断基準 | 初動・所有者 |
| --- | --- | --- | --- |
| MON-01 | Unknown、外部成功・台帳不一致 | 1分周期で抽出し日中5分以内に一覧化 | ITへ割当、15分以内に引受け |
| MON-02 | 誤開示・未確認実行・重大誤案内 | 1件でも重大として扱う | 該当経路停止、森・岡本・高橋へ |
| MON-03 | 一般回答・同期一往復 | P95 15秒／30秒の目標超過、件数・失敗率も確認 | 時間帯・接続先・待機を切り分け |
| MON-04 | 参照ツール・更新受領 | P95 5秒／3秒、受領できない要求 | 影響操作だけ縮退 |
| MON-05 | 引継ぎ未引受け・業務期限 | dueAt超過、受け手未設定 | SVが代替担当を割当 |
| MON-06 | 通知未送信・照合キュー | nextCheckAt超過、同じ要求の滞留 | 新規更新せず当該後処理を回復 |
| MON-07 | RPA対象不一致 | 0件、複数件、画面変更、認証画面 | 対象生産照会を停止、手動照会へ |
| MON-08 | ナレッジ公開・版 | 未承認版、旧版混入、公開区分不一致 | 該当文書を検索対象から除外し回帰 |
| MON-09 | 計測・日次集約 | 前回成功点の停滞、件数差、重複 | 月次報告を未確定とし再集計 |

少数サンプルでP95を断定せず、母数と観測区間を添える。同一障害の通知はrequestId・操作・障害種別で集約し、未解決の継続と新規発生を区別する。機密情報を監視通知の本文へ貼り付けない。

## 4. 障害手順

[第13章](../BOOK.md#chapter-13)の障害対応を、当番が判断に使う手順へ展開する。どの手順でも、検知、停止範囲、照合、再開条件、残る業務を明示する。技術的に応答が戻っただけで復旧完了にしない。

### F-1　RB-01 登録結果不明

**結果不明時の対応手順**

| 段階・担当 | すること | 完了の証拠 |
| --- | --- | --- |
| 検知／監視・SV | タイムアウトや台帳不一致を要求IDで抽出 | 5分以内に一覧。15分以内に運用担当が引受け |
| 停止／受付 | 新しいIDでの再登録を止め、Unknownにする | 確認中の案内と次回照合時刻 |
| 照合／連携運用 | 正本を要求ID・受付IDで確認。検索0件だけで未実行としない | 外部ログ、対象、入力版、存在件数 |
| 回復／連携運用 | 成功済みなら関連付け。未通知だけ再送 | 重複なし、外部IDと台帳が一致 |
| 保留／SV | 未実行を証明できなければ保留を維持 | 担当・期限・代替作業・顧客連絡 |
| 終了／SVとIT | 影響した他案件と通知を確認 | 残件一覧、原因、対策、回帰試験 |

時間外は技術障害を当番へ通知するが、顧客への折返しは有人時間に基づく。24時間の修理駆付けを約束しない。

### F-2　RB-02 保証・注文API停止

**参照連携を縮退する**

| 判断 | 処置 |
| --- | --- |
| 全件か一部か | 対象、接続主体、認証、有効期限、遅延を切り分ける |
| 個別確認が不能 | 保証の確定を止め、一般案内を継続する |
| 古い取得値がある | 取得時点と用途を確認。最新確認が必要な判断へ使わない |
| 代替手段 | 権限のある既存画面で照会し、確認者・日時・根拠を残す |
| 再開 | 接続成功と保留案件の再照会を確認し、次の行動を決める |

アクセス拒否を接続障害として繰り返し再試行しない。資格情報を会話や障害票の本文へ貼り付けず、管理された接続設定で扱う。

### F-3　RB-03 生産RPAの画面変更

**画面連携の停止と復帰**

| 担当 | 処置と判定 |
| --- | --- |
| RPA運用 | 対象照会を停止し、専用実行環境とログを確認。無関係な利用者プロセスを終了しない |
| 供給担当 | 手動照会で対象製品・製造指示・状態・日時・確認者を返す |
| 開発・品質 | 通常、0件、複数件、認証画面、計画未確定、時間切れを再試験 |
| IT・運用 | 正しい対象だけを返すことを確認し、少数照合後に再開 |
| 生産システム窓口 | 次の画面変更の通知先へRPA運用を追加 |

### F-4　RB-04 ナレッジの誤案内

**誤案内の封じ込めと再発防止**

| 順序 | 処置 |
| --- | --- |
| 1 保全 | 問い合わせ、対象機、回答、参照元、版を確保する |
| 2 封じ込め | 重大な誤案内なら対象経路を止め、既存窓口へ切替 |
| 3 原因確認 | 正本、重複、公開区分、索引、適用条件を確認 |
| 4 反映 | 承認版を登録し、旧版が検索に使われないことを確認 |
| 5 回帰 | 代表質問、類似機種、根拠なし、安全を確認 |
| 6 影響対応 | 追跡可能な案件へ訂正連絡が必要か業務責任者が判断 |

検索から除外することと、証拠として保存することを分ける。文書を消しても、既に伝えた案内の影響は消えない。

### F-5　RB-05 安全上の懸念

**安全対応の業務境界**

| 局面 | 対応 |
| --- | --- |
| 危険兆候の申告 | 通常の操作案内を中断し、承認済みの使用中止・安全確保案内へ |
| 現在進行する危険 | 修理受付の入力を優先せず、身の安全と適切な緊急対応を優先 |
| 安全確保後 | 事実、時刻、対象機、未確認事項、連絡手段を品質保証へ渡す |
| 専門判断 | 事故原因、再使用、補償、報告の要否は権限を持つ担当が判断 |
| 追跡 | 引受け担当と次の連絡を確認。通常の自動完了にしない |

### F-6　RB-06 公開・切戻し

**公開判定でそろえるもの**

| 確認者 | 確認する証拠 |
| --- | --- |
| 松田／スポンサー | 業務の開始範囲、残課題、代替手段、担当と期限 |
| 森／品質保証 | 規約、安全、根拠版、重大誤案内の対策 |
| 岡本／IT | 依存コネクタ、接続参照、環境変数、権限、DLP、監視 |
| 青木／品質担当 | 重大24件、総合、性能、移行・集計照合、再試験 |
| 高橋／現場 | 教育、当番表、引継ぎ、縮退と復帰の実技 |

切戻す際は対象ツールを止め、既存窓口へ案内し、互換性を確認して前版へ切り替える。新台帳の行、外部予約、承認を消して戻してはならない。未完了の実行と通知を突合して旧運用の担当へ渡す。再開は、原因箇所の修正、重大条件の回帰、残件突合、利用部門の確認がそろってから行う。
## 5. 変更・リリース・資格情報

開発・テスト・本番を分離し、開発者の接続をそのまま本番へ持ち込まない。作成者と本番配備者を分け、接続参照・環境変数・DLP・対象ロール・ナレッジ版を配備前後で照合する。更新権限が必要な接続と読取専用接続を分ける。

期限のある接続は期限と所有者を台帳へ登録する。担当者異動・退職時は接続所有者、サービス実行主体、通知先、RPA端末の実行資格を点検する。更新後は実利用者・実チャネルで代表照会と確認付き更新を再確認する。

権限変更・規約改訂・モデル変更は、見た目が変わらなくても回帰対象とする。根拠文書の公開作業は「新版を追加した」と「旧版が検索されない」を別々に確認する。

## 6. データ保持・削除・証拠保全

以下は本ケースの社内方針として設定する具体値であり、法定保存期間を意味しない。法令・契約・紛争対応等の保全理由がある対象は、森と岡本が解除条件を記録して削除保留にする。

| 区分 | ケース内の保持方針 | 削除・最小化 |
| --- | --- | --- |
| 案件・作業・費用判断の証拠 | 案件完了後5年 | 関連契約・紛争等の保留を先に判定。業務責任者が対象確認 |
| 承認・同意・重要変更履歴 | 関連案件と同期間 | 本文を重複コピーせず証拠参照を維持 |
| 短期的な技術診断ログ | 90日 | PII・トークンを記録しない。事件調査分は承認して保全 |
| 安全に匿名化した月次集計 | 3年 | 再識別できる細粒度の小集団を経営画面へ出さない |
| 確認下書き | 有効時間30分、完了・中止後30日で不要本文を削除 | 実行・同意の証拠に必要な版参照は案件側へ残す |
| 会話全文・添付の複製 | 原則として新台帳へ全面複写しない | 既存の管理された保管先と必要項目の参照を使用 |

削除対象抽出、保留除外、承認、実行、件数照合を記録する。実行要求や監査を先に消して外部更新の説明ができなくなる順序を避ける。

## 7. バックアップ・復旧・業務継続

バックアップの有効性、復旧権限、復旧先、保持される範囲は対象環境で確認する。SaaSの復旧仕様を自社の業務目標へそのまま読み替えない。30分は代替業務開始の訓練目標であり、基盤RTOの保証ではない。

復旧後は、復旧点以降の外部受付・引当・予約・承認と実行台帳を突合する。外部で成功した処理が復旧済み台帳に存在しない可能性があるため、ツールを再開する前に関連付けと通知を回復する。既存画面・差分受付票の業務も同じ対象へ二重登録しない。

## 8. 改善・終了の条件

事故・障害を閉じる条件は、サービスが応答すること、影響案件の状態と通知がそろうこと、残タスクに担当がいること、原因対策と回帰が記録されることの四点である。

月次では、追加接触率、工数、現金支出に加え、初回修理完了率、訪問待ち、部品欠品による再訪を確認する。受付の改善が技術員や物流の能力制約を解消したと仮定しない。
